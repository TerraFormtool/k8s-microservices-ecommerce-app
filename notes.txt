Step 1 — Verify your EKS cluster

Run:

aws eks list-clusters --region us-east-1

kubectl get nodes

kubectl get pods -n retail

kubectl get deployment -n kube-system aws-load-balancer-controller

Step 2 — Set variables

On your EC2/admin machine:

export CLUSTER_NAME="YOUR-EKS-CLUSTER-NAME"
export AWS_REGION="us-east-1"
export AWS_ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)

echo $CLUSTER_NAME
echo $AWS_REGION
echo $AWS_ACCOUNT_ID


Step 4 — Check eksctl
eksctl version

If installed, continue.

Also check:

helm version

Step 5 — Configure OIDC

Run:

aws eks describe-cluster \
  --name "$CLUSTER_NAME" \
  --region "$AWS_REGION" \
  --query 'cluster.identity.oidc.issuer' \
  --output text

eksctl utils associate-iam-oidc-provider \
  --cluster "$CLUSTER_NAME" \
  --region "$AWS_REGION" \
  --approve

If it says the provider already exists, that's okay.

IRSA uses the cluster-specific OIDC provider for the controller's IAM permissions.

Step 6 — Download IAM policy
cd /tmp
curl -O https://raw.githubusercontent.com/kubernetes-sigs/aws-load-balancer-controller/v2.14.1/docs/install/iam_policy.json

ls -lh /tmp/iam_policy.json

Step 7 — Create IAM policy
aws iam create-policy \
  --policy-name AWSLoadBalancerControllerIAMPolicy \
  --policy-document file:///tmp/iam_policy.json

If you get:

EntityAlreadyExists

don't worry. It means the policy already exists.

Check:

aws iam get-policy \
  --policy-arn arn:aws:iam::${AWS_ACCOUNT_ID}:policy/AWSLoadBalancerControllerIAMPolicy

Step 8 — Create IAM ServiceAccount

Run:

eksctl create iamserviceaccount \
  --cluster "$CLUSTER_NAME" \
  --namespace kube-system \
  --name aws-load-balancer-controller \
  --attach-policy-arn arn:aws:iam::${AWS_ACCOUNT_ID}:policy/AWSLoadBalancerControllerIAMPolicy \
  --override-existing-serviceaccounts \
  --region "$AWS_REGION" \
  --approve

This creates the relationship:

IAM Policy
     |
     v
IAM Role
     |
     v
Kubernetes ServiceAccount
     |
     v
aws-load-balancer-controller

AWS documents this exact eksctl create iamserviceaccount approach.

Step 2 — Manually recreate the Kubernetes ServiceAccount

Since the IAM role already exists, create the missing Kubernetes ServiceAccount yourself.

Run:

kubectl create serviceaccount \
  aws-load-balancer-controller \
  -n kube-system

Then annotate it:

kubectl annotate serviceaccount \
  aws-load-balancer-controller \
  -n kube-system \
  eks.amazonaws.com/role-arn="$LBC_ROLE_ARN" \
  --overwrite

This is the standard IRSA relationship:

Kubernetes ServiceAccount
        |
        | annotation
        v
IAM Role
        |
        v
AWSLoadBalancerControllerIAMPolicy

AWS documents this ServiceAccount-to-IAM-role annotation mechanism for IRSA.

Step 4 — Verify the IAM trust policy

This is very important before installing the controller.

Run:

aws iam get-role \
  --role-name eksctl-prod-eks-addon-iamserviceaccount-kube--Role1-jxgy2Okh43hC \
  --query 'Role.AssumeRolePolicyDocument'

You should find a trust relationship allowing:

sts:AssumeRoleWithWebIdentity

and the subject should correspond to:

system:serviceaccount:kube-system:aws-load-balancer-controller

AWS requires the IAM role trust policy to reference the cluster's OIDC provider and the specific Kubernetes ServiceAccount.

If you want a cleaner check

Run:

aws iam get-role \

Step 10 — Install Helm chart

Add AWS's EKS chart repository:

helm repo add eks https://aws.github.io/eks-charts

Then:

helm repo update eks

Check available versions:

helm search repo eks/aws-load-balancer-controller --versions | head

AWS's current documented Helm chart installation uses chart version 1.14.0.

Install:

helm install aws-load-balancer-controller \
  eks/aws-load-balancer-controller \
  -n kube-system \
  --set clusterName="$CLUSTER_NAME" \
  --set serviceAccount.create=false \
  --set serviceAccount.name=aws-load-balancer-controller \
  --version 1.14.0

Step 15 — Create ALB Ingress

Create:

k8s/ingress/retail-ingress.yaml

Use:

apiVersion: networking.k8s.io/v1
kind: Ingress

metadata:
  name: retail-ingress
  namespace: retail

  annotations:

    # Internet-facing ALB
    alb.ingress.kubernetes.io/scheme: internet-facing

    # Send traffic directly to Pod IPs
    alb.ingress.kubernetes.io/target-type: ip

    # ALB HTTP listener
    alb.ingress.kubernetes.io/listen-ports: '[{"HTTP":80}]'

    # UI health check
    alb.ingress.kubernetes.io/healthcheck-path: /actuator/health

    alb.ingress.kubernetes.io/healthcheck-port: traffic-port

    alb.ingress.kubernetes.io/success-codes: "200"

spec:

  ingressClassName: alb

  rules:

    - host: retail.metatechz.store

      http:

        paths:

          - path: /

            pathType: Prefix

            backend:

              service:
                name: ui
                port:
                  number: 80

The AWS Load Balancer Controller creates an ALB when it sees this Kubernetes Ingress.

Step 16 — Apply Ingress
kubectl apply -f k8s/ingress/retail-ingress.yaml

Then:

kubectl get ingress -n retail

Initially:

NAME             CLASS   HOSTS                    ADDRESS   PORTS
retail-ingress   alb     retail.yourdomain.com              80

Wait:

kubectl get ingress -n retail -w

After a few minutes you should get:

NAME             CLASS   HOSTS                    ADDRESS
retail-ingress   alb     retail.yourdomain.com   k8s-retail-xxxx.us-east-1.elb.amazonaws.com

The controller provisions the AWS ALB and target groups based on the Ingress configuration.

Part 10 — Add HTTPS to your Ingress

Once ACM gives you the certificate ARN, for example:

arn:aws:acm:us-east-1:302524629943:certificate/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxx

Update your Ingress:

apiVersion: networking.k8s.io/v1
kind: Ingress

metadata:
  name: retail-ingress
  namespace: retail

  annotations:

    alb.ingress.kubernetes.io/scheme: internet-facing

    alb.ingress.kubernetes.io/target-type: ip

    alb.ingress.kubernetes.io/listen-ports: '[{"HTTP":80},{"HTTPS":443}]'

    alb.ingress.kubernetes.io/certificate-arn: arn:aws:acm:us-east-1:302524629943:certificate/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxx

    alb.ingress.kubernetes.io/ssl-redirect: "443"

    alb.ingress.kubernetes.io/healthcheck-path: /actuator/health

    alb.ingress.kubernetes.io/healthcheck-port: traffic-port

    alb.ingress.kubernetes.io/success-codes: "200"

spec:

  ingressClassName: alb

  rules:

    - host: retail.metatechz.store

      http:

        paths:

          - path: /

            pathType: Prefix

            backend:

              service:
                name: ui
                port:
                  number: 80

Notice the important part:

alb.ingress.kubernetes.io/listen-ports: '[{"HTTP":80},{"HTTPS":443}]'

and:

alb.ingress.kubernetes.io/ssl-redirect: "443"

So:

HTTP :80
   |
   v
redirect
   |
   v
HTTPS :443
